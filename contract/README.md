# The Dispatch wire contract

This directory is the **single source of truth** for what every Dispatch SDK must put on
the wire. With SDKs in three-plus languages, the contract — not any one implementation — is
the product. Everything here is consumed by SDK test suites and by the backend's own
request specs.

## What's here

| Path | What it is |
| --- | --- |
| `openapi/tickets.yaml` | OpenAPI 3.1 for the two ingest endpoints (`/api/v1/tickets`, `/api/v1/store`). |
| `schema/event.schema.json` | JSON Schema (2020-12) for the Sentry-shaped **error event**. |
| `schema/ticket.schema.json` | JSON Schema for the **ticket create request**. |
| `fixtures/*.json` | **Golden fixtures** — canonical payloads every SDK must reproduce/accept. |
| `scripts/validate.mjs` | Validates every fixture against the schemas (the cheapest conformance gate). |

## The two payloads, two endpoints

1. **Tickets** — `POST {endpoint}` (default `https://{tenant}.dispatchit.app/api/v1/tickets`).
   Curated feedback (bugs, feature requests, suggestions) from the widget and from
   programmatic `report()`. Auth:
   `Authorization: Bearer dsp_live_…`. Optional `Idempotency-Key` (UUID, 24h replay window) and
   `X-Dispatch-Widget-Version`. Body: `ticket.schema.json`. Response: `{ id, status, url }`.
2. **Errors** — `POST {error_endpoint}` (default: the tickets endpoint with the last path
   segment swapped to `/store`). Sentry-compatible events. Auth: `Authorization: Bearer` +
   `X-Dispatch-Sdk`. On browser page-unload the tracker falls back to `navigator.sendBeacon`,
   which can't set headers, so the token goes in `?sentry_key=` instead. Body:
   `event.schema.json`.

## Invariants (constants are part of the contract)

These come straight from the `dispatch-rails` reference producer and must hold in every SDK:

- Cause chain ordering: **oldest cause first, the raised exception last**. Capped at **5** causes.
- Stack frames: **oldest first, the failing frame last**. Capped at **100** frames.
- Source context: up to **5** lines of `pre_context`/`post_context` around `context_line`, added
  to in-app frames only, for at most **12** frames per event.
- `value` (exception message) truncated to **2000** chars.
- Opt-in request `data` capped at **8000** bytes, else `{ "_truncated": true }`.
- Transport queue is bounded at **100** events, **drop-on-overflow** (never block, never grow
  unbounded).
- `mechanism.handled` is `false` for unhandled (middleware/global-handler) captures, `true` for
  manual `captureException`.
- `in_app` heuristic is per-language: ruby excludes `/gems/ /vendor/ /ruby/`; javascript excludes
  `node_modules` (and requires an http(s) URL); python excludes `site-packages`/stdlib.

Only `platform` and the `in_app` heuristic legitimately differ across languages. Everything else
about the shape is identical.

## Golden fixtures

| Fixture | Producer | Shows |
| --- | --- | --- |
| `event.ruby-request-exception.json` | gem (real) | unhandled request error; request+user+tags; source context; one dependency frame |
| `event.ruby-cause-chain.json` | gem (real) | 3-deep cause chain, oldest-first ordering |
| `event.ruby-background-job.json` | gem (real) | job error with **no** request → no `transaction`/`request`/`user` |
| `event.ruby-manual-handled.json` | gem (real) | `mechanism.handled: true`, `level: "warning"` |
| `event.js-onerror.json` | hand-authored | browser `window.onerror`; `breadcrumbs` + `user_path`; `colno` on frames |
| `event.js-unhandledrejection.json` | hand-authored | browser unhandled promise rejection |
| `event.python-traceback.json` | hand-authored | **target** the Python SDK must produce |
| `ticket.widget.json` | hand-authored | full widget submission incl. base64 screenshot |
| `ticket.api-report.json` | hand-authored | programmatic `report()` with `correlation_id` |

The Ruby fixtures are generated by the gem (see below). The browser fixtures mirror the gem's
bundled `error_tracker.js` output; the Python one is the goal the Python SDK is built against.

### Stable vs. volatile fields

A conformance test must **not** assert byte-equality — some fields are inherently per-run.
Normalize these before comparing (the fixtures already carry fixed sentinels for them):

- **Always volatile:** `event_id` (`"0"×32` here), `timestamp` (`1700000000.0`), `server_name`
  (`"web.1.dispatch.internal"`), breadcrumb `timestamp`s.
- **Per-machine:** `abs_path` (normalized to a `/srv/app/…` root here) and the literal source
  lines in `pre/post_context` (depend on the checked-out source).
- **Assert on:** field **names**, **nesting**, **ordering** (cause + frame order), `in_app` flags,
  `mechanism`, the limits, and `platform`.

> Note on `mechanism.type`: `@dispatchitapp/browser` distinguishes `"onerror"` (window.onerror) from
> `"onunhandledrejection"` (unhandled promise rejections), and `event.js-unhandledrejection.json`
> reflects that. The gem's older bundled `error_tracker.js` emits `"onerror"` for both — the
> schema permits any mechanism type, so both interoperate.

## Regenerating the Ruby fixtures

The gem is the reference producer. From the product repo (`dispatch/`):

```bash
bundle exec ruby gems/dispatch-rails/script/dump_fixtures.rb
```

It feeds `EventBuilder` synthetic exceptions with deterministic backtraces and writes the
normalized JSON here (default output: this `fixtures/` directory). Re-run it whenever
`event_builder.rb` changes, and commit the diff — a surprising diff means the wire shape moved
and every SDK must follow.

## Validating

```bash
pnpm install
pnpm --filter @dispatchitapp/contract validate
```

In each SDK, validate freshly-produced payloads against these schemas (`ajv` in JS,
`jsonschema` in Python, etc.) before asserting the HTTP call — it catches drift immediately.
